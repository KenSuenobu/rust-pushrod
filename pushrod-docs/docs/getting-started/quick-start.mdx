# Quick start

import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

:::tip[TL;DR]
Install SDL2 (with SDL2_ttf and SDL2_image), add `pushrod` and `sdl2` to `Cargo.toml`, copy a font into `assets/`, paste one of the two programs below into `src/main.rs`, and run `cargo run`. Pick the style you prefer: **callbacks** (Pushrod runs the loop and calls your code) or **your own event loop** (you ask Pushrod for the next event and `match` on it).
:::

You'll build this: a label and a button; each click updates the label.

![The quick-start application](/img/screenshots/quick-start.png)

## 1. Install SDL2

Ubuntu/Debian:

```bash
sudo apt install libsdl2-dev libsdl2-ttf-dev libsdl2-image-dev
```

macOS (Homebrew): `brew install sdl2 sdl2_image sdl2_ttf`. Other systems: see [Installation](./installation.md).

## 2. Create a project

```bash
cargo new hello-pushrod
cd hello-pushrod
```

## 3. Add the dependencies

In `Cargo.toml`:

```toml
[dependencies]
pushrod = { git = "https://github.com/KenSuenobu/rust-pushrod" }
pushrod-widgets = { git = "https://github.com/KenSuenobu/rust-pushrod" }

[dependencies.sdl2]
version = "^0.36.0"
features = ["ttf", "image", "unsafe_textures"]
```

`pushrod` is the core (engine, events, drawing); `pushrod-widgets` has the standard widgets. Pushrod requires Rust 1.86 or newer. The `unsafe_textures` feature is required: it lets Pushrod keep one GPU texture per widget.

## 4. Add a font

Pushrod draws text with a TrueType font. Copy the one that ships with Pushrod:

```bash
mkdir assets
curl -L -o assets/OpenSans-Regular.ttf https://github.com/KenSuenobu/rust-pushrod/raw/main/assets/OpenSans-Regular.ttf
```

## 5. Write the program

Replace `src/main.rs` with either version. Both build the same window and behave the same way.

<Tabs groupId="app-style">
<TabItem value="callbacks" label="Callbacks" default>

Pushrod runs the event loop; you register a callback for the button.

```rust title="src/main.rs"
use pushrod_widgets::button_widget::ButtonWidget;
use pushrod::engine::Engine;
use pushrod::geometry::{point, size};
use pushrod_widgets::text_widget::{TextJustify, TextWidget};
use sdl2::pixels::Color;
use sdl2::ttf::FontStyle;

const FONT: &str = "assets/OpenSans-Regular.ttf";

/// Application state: passed to every callback as `&mut Counter`.
#[derive(Default)]
struct Counter {
    clicks: u32,
}

fn main() {
    let sdl = sdl2::init().unwrap();
    let window = sdl
        .video()
        .unwrap()
        .window("Hello, Pushrod", 400, 140)
        .position_centered()
        .build()
        .unwrap();

    let mut engine: Engine<Counter> = Engine::new(size(400, 140), 60);

    let label = engine.add_widget(TextWidget::new(
        point(20, 20),
        size(360, 24),
        FONT.into(),
        FontStyle::NORMAL,
        16,
        Color::BLACK,
        TextJustify::Left,
        "Not clicked yet.".into(),
    ));

    let button = engine.add_widget(ButtonWidget::new(
        point(20, 70),
        size(120, 30),
        FONT.into(),
        FontStyle::NORMAL,
        16,
        Color::BLACK,
        TextJustify::Center,
        "Click me".into(),
        2,
    ));

    engine.on_click(button, move |state, ui| {
        state.clicks += 1;

        if let Some(text) = ui.get_mut::<TextWidget>(label) {
            text.set_text(format!("Clicked {} time(s).", state.clicks));
        }
    });

    let state = engine.run(sdl, window, Counter::default());

    println!("Clicked {} time(s) in total.", state.clicks);
}
```

<TabItem value="event-loop" label="Event loop">

You run the loop: `next_event` waits for input, keeps the screen up to date, and returns each event the widgets generate; `match` on the ones you care about. It returns `None` when the window closes.

```rust title="src/main.rs"
use pushrod_widgets::button_widget::ButtonWidget;
use pushrod::engine::Engine;
use pushrod::event::PushrodEvent;
use pushrod::geometry::{point, size};
use pushrod_widgets::text_widget::{TextJustify, TextWidget};
use sdl2::pixels::Color;
use sdl2::ttf::FontStyle;

const FONT: &str = "assets/OpenSans-Regular.ttf";

fn main() {
    let sdl = sdl2::init().unwrap();
    let window = sdl
        .video()
        .unwrap()
        .window("Hello, Pushrod", 400, 140)
        .position_centered()
        .build()
        .unwrap();

    let mut engine: Engine = Engine::new(size(400, 140), 60);

    let label = engine.add_widget(TextWidget::new(
        point(20, 20),
        size(360, 24),
        FONT.into(),
        FontStyle::NORMAL,
        16,
        Color::BLACK,
        TextJustify::Left,
        "Not clicked yet.".into(),
    ));

    let button = engine.add_widget(ButtonWidget::new(
        point(20, 70),
        size(120, 30),
        FONT.into(),
        FontStyle::NORMAL,
        16,
        Color::BLACK,
        TextJustify::Center,
        "Click me".into(),
        2,
    ));

    let mut clicks = 0;
    let mut events = engine.event_loop(&sdl, window);

    // Your own event loop: next_event() waits for input, keeps the screen up to date,
    // and returns each event the widgets generate. It returns None when the window closes.
    while let Some(event) = engine.next_event(&mut events) {
        match event {
            PushrodEvent::Clicked(id, _) if id == button => {
                clicks += 1;

                if let Some(text) = engine.widgets().get_as_mut::<TextWidget>(label) {
                    text.set_text(format!("Clicked {} time(s).", clicks));
                }
            }

            _ => {}
        }
    }

    println!("Clicked {} time(s) in total.", clicks);
}
```

## 6. Run it

```bash
cargo run
```

Click the button: the label counts your clicks. Close the window and the final count is printed, because `engine.run` returns your application state.

## What just happened

- `Engine` owns the window's widget tree. With callbacks, its type parameter is your state type (`Engine<Counter>`); in the event-loop version you keep state in local variables, so it's plain `Engine`.
- `add_widget` added each widget to the window and returned its `WidgetId`.
- **Callbacks:** `on_click(button, ..)` registered code that runs for that button. It receives `&mut Counter` and a `Ui` handle, which finds widgets by ID (`ui.get_mut::<TextWidget>(label)`). `engine.run` ran the loop until the window closed, then gave the state back.
- **Event loop:** `engine.event_loop(&sdl, window)` opened the window for drawing, and each `engine.next_event(&mut events)` returned the next event, such as `PushrodEvent::Clicked(id, clicks)`. You change widgets directly through `engine.widgets()`. The call blocks while nothing happens, so the loop doesn't spin.

Both styles route input through the same widgets and produce the same events; see [Handling events](../guides/handling-events.md#two-ways-to-handle-events) for when to choose which.
